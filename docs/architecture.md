# Архитектура и правила обработки

Подробное описание решения. Начало работы и примеры входа/выхода — в [README](../README.md).

## Карточки книг и подтверждённые варианты

`book_merges` хранит направленные, обратимые связи между предварительными ID; исходные записи не удаляются. `book_profiles` хранит выбранное основное представление. Каноническая карточка вычисляется из группы: исходные ID, строки, варианты пар «название + автор», форматы и URL. Подтверждённые варианты участвуют в RapidFuzz и в поиске внутри сборников, а также передаются AI как известные aliases. Варианты из разных неподтверждённых групп не смешиваются.

Предложения объединения формируются кодом по блокам токенов названия и точным названиям. При подключённом AI фоновый этап разбирает их после импорта и перед обработкой страниц. `AutoGrouper` ограничивает число пар в порции и число страниц источников (не более двух на пару), использует общий AI-кэш, бюджет и JSON-схему. Модель возвращает same / different / uncertain. Для same нужны проверка кодом: совместимость опечаток / инициалов всех вариантов при уверенности ≥0.90 либо дословная цитата с явной связью псевдонимов при одинаковом названии при уверенности ≥0.95. Самооценка модели отдельно не считается доказательством. Альтернативные названия автоматически не объединяются. Значимые числа / номера томов и эталонные ID защищены.

`ai_group_decisions` хранит состояние, причины, проверенные цитаты, модель и отпечаток входных карточек. Изменение исходных вариантов допускает новую оценку; неизменные пары не вызывают повторных запросов. Ошибка AI / бюджета переводит оставшиеся пары в deferred без автоматического платного повтора. Нерешённые пары можно повторно оценить через API / админку. Обработчики страниц ждут завершения фонового этапа, затем продолжают даже при uncertain / deferred. Ручное исправление необязательно; отмена связи запрещает её автоматическое восстановление. Изменения данных / ручного решения во время вызова AI проверяются перед применением ответа.

Исходные ячейки и история старых проверок остаются неизменными. В обработанных строках пересчитываются связи и текущие неоднозначности; исходные замечания сохраняются отдельно. Наличие связи не подтверждает размещение контента: для статуса 1 всё равно требуются факты страницы и признаки.

## Правила первой части

Исходные значения хранятся неизменно в `records.raw`, связь сохраняется через ID импорта, название листа и номер строки. В отдельных полях применяются Unicode NFKC, регистр, ё/е и разделение пунктуации для **поиска**. Авторский ключ допускает перестановку слов. Служебный ключ URL убирает fragment, но сохраняет query: параметры могут отличать размещения.

Точная группа «название + авторский ключ + формат» получает предполагаемый ID книги. Равные URL — дубли размещения; разные URL той же книги — отдельные размещения, которые не удаляются. Одинаковое название у разных авторов не объединяется. Псевдонимы, альтернативные названия и разные издания требуют эталонного ID / ISBN / подтверждённых алиасов. Неоднозначности остаются в отчёте. При новом импорте существующие источники сохраняются; повтор того же файла идемпотентен.

RapidFuzz возвращает кандидатов по названию и автору, не окончательную «истину». Номера томов проверяются отдельно. В сборниках учитывается явный перечень включённых книг вместе с автором. Источник решения, область совпадения и признаки сохраняются в результате.

## Конвейер и AI

```text
Excel / каталог → SQLite → очередь → HTTP → извлечение HTML/PDF
                                  ↘ Playwright при необходимости
                кандидаты RapidFuzz → проверка совпадения и доказательств
                                  ↘ ограниченный AI-цикл → отчёт 0/1/2
```

Основные проверки выполняются кодом. Агентский цикл написан явно в `monitor/engine.py`; LangChain и LangGraph не требуются. AI подключается при неоднозначных фактах или отсутствии признаков; получает короткий текст и несколько кандидатов, возвращает JSON, который валидируется Pydantic. Цитаты должны присутствовать в тексте; название и автор не берутся из ожиданий пользователя. Агент может прочитать наблюдаемую ссылку на том же хосте или запросить браузерный вариант. Максимум два AI-шага на страницу; регистрации, отправки форм, скачивания исполняемых файлов и свободного исполнения кода нет.

JSON-LD, основной заголовок, автор, явные ссылки FB2/EPUB/TXT/PDF/torrent, читалка и аудиоплеер собираются как признаки. Рекомендации и комментарии исключаются, насколько позволяет общий DOM-парсер. Ссылка / плеер — **признак**, а не доказательство доступности полного файла или незаконности размещения. Аннотация сама по себе не подтверждает наличие полного текста. Части сложных сайтов требуют отдельных адаптеров; универсальный парсер не гарантирует полноту.

### Статусы

- **1:** книга сопоставлена, есть наблюдаемые признаки размещения.
- **0:** доступная страница проверена, совпадение / размещение не подтвердилось; включая 404/410 и другой формат при `scope=format`.
- **2:** доступ, извлечение, неоднозначность или необходимый AI-анализ не позволили определить результат.

Техническое состояние очереди хранится отдельно: `pending`, `running`, `retry`, `done`, `needs_attention`. Не надо трактовать `done` как подтверждение размещения.

## Ошибки, CAPTCHA и регистрация

Сетевые ошибки, 429, 5xx, ошибки JavaScript и тайм-ауты получают ограниченные повторы с экспоненциальной задержкой и учётом числового Retry-After. После исчерпания попыток задача требует внимания. 403, CAPTCHA, необходимость входа, битый/зашифрованный PDF, превышение размера, отсутствие OCR и ошибки схемы не превращаются в отрицательное совпадение. События видны в терминале, `data/service.log` и админке.

При CAPTCHA / входе сохраняется снимок страницы. Кнопка «Разобрать снимок сильной моделью» запускает отдельную vision-модель: определяет тип препятствия и может предложить текст простой видимой CAPTCHA. Это **подсказка для человека**. reCAPTCHA, Turnstile, защитные токены и автоматическая регистрация не реализованы. Команда `session` открывает видимый браузер: оператор сам решает проверку, вводит учётные данные и принимает необходимые условия. По Enter сохраняется сессия только для выбранного домена. После этого задача повторяется. Если сайт привязывает разрешение к браузеру, IP или короткому сроку, повтор всё равно может потребовать участия человека.

Сессии имеют права 0600; ключ остаётся во внешнем файле. URL с credentials, внутренними IP и нестандартными портами запрещены, редиректы проверяются, браузерные POST блокируются в автоматическом исследовании. Для промышленного развёртывания нужна также изоляция исходящего трафика: текущая проверка DNS не заменяет сетевой firewall против DNS rebinding.

## Стоимость AI

Основная модель: `gpt-4.1-mini`. Для диагностики снимка: `gpt-4.1`, только по кнопке оператора. Модели выбираются настройками и не меняются автоматически. На 14.10.2026 публичный каталог AI Tunnel сообщал 80 ₽ / 1 млн входных и 320 ₽ / 1 млн выходных токенов для основной модели. Перед вызовами сервис запрашивает актуальные цены и баланс.

По умолчанию лимит составляет 10 ₽ за скользящие 24 часа, 5 ₽ на проверку, остановка AI при балансе ниже 20 ₽. Кэш повторного AI-запроса — 7 дней, HTTP-результата — 1 час; при ручном повторе страница загружается заново. Стоимость записывается из `usage.cost_rub` / `usage.cost`, при сетевой неопределённости резервируется верхняя оценка. Бюджеты проверяются последовательно, чтобы одновременные запросы не расходовали один и тот же остаток. Это локальный лимит процесса, не ограничение всех приложений, использующих API-ключ.

Источники: [AI Tunnel: баланс](https://aitunnel.ru/docs/payments), [модели и цены](https://aitunnel.ru/docs/models), [схема API](https://aitunnel.ru/docs/api-reference).

## Тесты и проверка

```bash
.venv/bin/pytest -q
```

Проверяются исходные строки и идемпотентность импорта, авторы и тома, неоднозначность названий, сборники, отличия форматов, игнорирование рекомендаций, CAPTCHA и загрузочная оболочка, сетевые ошибки и повторы, защита от внутренних URL, API и Origin, CSV formula injection, лимит платных запросов и некорректный JSON от модели. Реальные URL дополнительно прогоняются через CLI / админку; их доступность меняется со временем. Наличие тестов не подтверждает достоверность исходного предварительного каталога.

## Масштабирование (часть 3)

При миллионе URL заменить локальную SQLite-очередь на PostgreSQL и распределённую очередь, отделить HTTP-workers от ограниченного пула браузеров. Планировать задания по доменам с адаптивной частотой, паузами при 429/403 и ограничением одновременных соединений. Дедуплицировать URL и содержимое, проверять изменения и переиспользовать результаты. Каталог индексировать по автору/названию; embeddings вводить после оценки пропущенных совпадений. Известные сайты обслуживать проверенными адаптерами, AI направлять неоднозначные записи и новые структуры; предложенные AI-селекторы проверять до применения. Человеку оставлять спорные связи книг, доступ и правовую оценку. Качество контролировать на размеченной выборке по доменам/форматам, отдельно измеряя ложные статусы 1, пропуски, долю статуса 2, полноту извлечения, сбои адаптеров, задержку очереди и стоимость корректного результата. Хранить версии правил/моделей, цитаты, дату проверки и историю решений. Предусмотреть недоступность сайтов, редиректы, сборники, смену структуры, истёкшие сессии, prompt injection и низкий баланс. Текущая локальная версия — рабочий прототип; указанные распределённые компоненты не реализованы.
