# Выводы по выполнению тестового задания

**Проект:** Book Monitor — локальный сервис для обработки списка книг и проверки признаков размещения контента по заданным URL.

**Репозиторий:** [github.com/artemius125/book-monitor](https://github.com/artemius125/book-monitor).

## Результат реализации

Решение реализовано программно как сервис с веб-админкой, REST API и командами терминала. На вход поступают Excel со списком книг и ссылок либо отдельный список URL; при необходимости подключается эталонный каталог книг.

Сервис сохраняет исходные строки, выявляет повторные ссылки и варианты записей, сопоставляет книги и проверяет содержимое доступных страниц. На выходе формируются обработанная таблица и результаты проверки в CSV / JSON: статус, причины решения, признаки размещения и сведения об источнике. В админке доступны фильтры, просмотр подробностей и экспорт выбранных строк.

Типовые операции выполняются кодом. AI используется для неоднозначных записей и сложных страниц через собственный ограниченный агентский цикл. После импорта AI автоматически разбирает варианты книг; подтверждённые связи участвуют в последующем сопоставлении. Причины решений сохраняются, объединение можно отменить. Если доказательств недостаточно, записи остаются раздельными, а обработка продолжается.

## Использованные технологии

- **Язык и сервис:** Python 3.12, FastAPI, SQLite.
- **Excel:** openpyxl.
- **Загрузка и разбор страниц:** HTTPX, BeautifulSoup, Playwright.
- **PDF:** pypdf.
- **Нечёткое сопоставление:** RapidFuzz.
- **AI:** OpenAI-совместимый API, собственный агентский цикл; текущий провайдер — AI Tunnel, основная модель — gpt-4.1-mini.
- **Веб-админка:** HTML, CSS, JavaScript.
- **Проверка:** pytest, GitHub Actions, проверки интерфейса через Playwright.

## Проверка и границы решения

В актуальном автоматическом прогоне прошли 45 тестов; один необязательный тест исходного Excel пропущен. Проверены сохранение данных, сопоставление, объединение вариантов, ошибки доступа, повторы, ограничения расходов AI и экспорт. Интеграционная проверка через реальный AI API подтвердила автоматическое объединение записей с опечаткой и повторное использование кэша.

Сервис проверяет переданные URL; самостоятельный поиск по интернету не реализован. Результат показывает признаки размещения, а не юридическое заключение о нарушении. Полнота файла — ознакомительный фрагмент или полное произведение — отдельно не определяется; такая проверка может стать следующим этапом развития. Аудио не прослушивается. CAPTCHA и регистрация требуют участия человека.

Основной проверенный запуск — Linux с Python 3.12. Docker-конфигурация подготовлена, но контейнерный запуск отдельно не проверялся. Инструкции запуска и настройки находятся в [README](../README.md); детали проверки — в [VERIFICATION](../VERIFICATION.md). API-ключ передаётся отдельно и хранится локально, секреты в репозиторий не включены.

## Часть 3 Масштабирование

Ниже приведён план развития для 1 000 000 URL и каталога из десятков тысяч книг. Распределённые компоненты относятся к будущей архитектуре.

### 1 Что автоматизировать в первую очередь

Распределение заданий, устранение повторных запросов, кэширование и проверку изменений страниц. SQLite заменить на PostgreSQL и распределённую очередь; HTTP-загрузку отделить от ограниченного пула браузеров. Скорость регулировать по доменам, каталог индексировать по автору и названию. Известные страницы обрабатывать кодом, AI подключать для неоднозначностей и новых структур.

### 2 Что оставить человеку

Редкие спорные случаи, которые AI не разрешил по доступным доказательствам, CAPTCHA, регистрацию и оценку законности размещения. Ручной разбор должен быть дополнительным этапом; неопределённость не должна останавливать всю очередь.

### 3 Как контролировать качество

Использовать размеченную выборку разных сайтов, форматов и сложных случаев. После изменения правил или модели повторно проверять выборку и проводить выборочный ручной аудит. Сохранять цитаты, источники, дату и версии обработчиков.

### 4 Какие ошибки и ограничения предусмотреть

Недоступность сайтов, блокировки, истечение сессий, редиректы, смену разметки, неполное извлечение, ошибки AI и исчерпание бюджета. Ограничивать повторы, увеличивать паузы при ограничениях сайта. Недоступную страницу не считать отсутствием контента. Проверять пропускную способность нагрузочными испытаниями с учётом ограничений сайтов.

### 5 Какие метрики использовать

Точность и полноту обнаружения совпадений, долю неопределённых результатов, ошибки по доменам, скорость обработки, время ожидания в очереди, долю обращений к AI и стоимость корректного результата.
